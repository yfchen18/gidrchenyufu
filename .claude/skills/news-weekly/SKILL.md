# 寫一期新知週報

先讀 `CLAUDE.md`（寫稿規則與查證流程）與 `docs/news-authoring.md`（欄位規格）。
這份只講週報特有的部分。

## 開始前先確認

1. **素材從哪來？** 醫師自己查證好的 markdown（最常見）／他指定的研究／要你去查。
   如果是他給的文件，**忠實依那份寫，不要自己加研究或數字**。
   （週報和衛教文章不同，**素材由他提供**，不需要先去讀電子書筆記。）
2. **站上講過了嗎？** `grep -ril "<關鍵詞>" src/content/` 看一下。
   週報本來就會回頭提既有文章，重複不是問題——但要**連過去**，而不是重寫一遍。
3. **日期。** 檔名、`published`、`reviewed` 都用發布當天。
4. **`sources_period` 填不出來就不要填。** 這個欄位是選填。如果素材的時間散布很廣、
   不是集中在某一週，硬填一個區間就是假的——留空，並告訴醫師為什麼。

## 檔名

`YYYY-MM-DD-英文小寫短語.md` → `/news/<檔名>/`

只用小寫英文、數字、連字號。**發布後不要改檔名**，改了舊網址會 404。

## 內容結構

跟著既有幾期的樣子走（`src/content/news/2026-10-26-*.md` 是好範本）：

1. **開場兩三句**：用問句把這期的主題串起來，粗體標出關鍵詞。
   **不要寫來源說明段落**（「我從某週的 X 貼文挑出⋯⋯」）——醫師刪過兩次。
2. **每個主題一個 `##`**，標題就把結論講完，不要賣關子。
   限制如果很重要，就直接放進標題（例：「但那是一個只有 40 人的試驗」）。
3. 每節裡面：研究怎麼做的 → 數字（能做成表格就做）→ **怎麼解讀／有哪些限制** →
   **對台灣的意義**（如果有）。
4. 適合的地方放一行「延伸閱讀：[⋯](/articles/<slug>/)」，網址取自
   `docs/news-authoring.md` 末尾那張表。
5. 結尾固定兩段：`## 給讀者的N個提醒`，然後是既有各期都有的那段門診資訊收尾
   （直接從上一期複製）。

內文從 `##` 開始，**不要寫 `# 標題`**（頁面已用 title 當 H1）。
免責聲明、作者資訊、日期、參考文獻、FAQ 區塊與結構化資料都會自動產生，不要寫進內文。

## frontmatter 的坑

- 日期一律 `YYYY-MM-DD`，寫 `2026/10/30` 會 build 失敗。`sources_period` 是文字，可用斜線。
- **所有文字欄位都加雙引號**最保險（半形冒號、`#`、開頭的 `[`、`{`、`*`、`&`、`!`、`>`
  都會讓 YAML 解析失敗）。字串內要用引號時改用「」。
- 縮排用空白不用 Tab。`faq` 的鍵名必須是 `q`／`a`；`references` 必須是 `text`（可加 `url`）。
- `faq` 寫 4 到 5 則，問法要像病人真的會問的（「吃 8 週就夠了嗎？」而不是
  「關於療程長度之探討」）。
- `references` 只列有 DOI 或官方網址的，照醫師給的資料原樣列。

## 寫完之後

1. build：`npx -y node@22 node_modules/astro/bin/astro.mjs build`
2. 驗證（見 `CLAUDE.md` 的發布流程）：結構化資料、站內連結、列表頁、sitemap，
   有表格的話在 375px 量一次有沒有橫向溢出
3. `git fetch origin` → 確認沒落後 → commit → push
4. 用 `until` 迴圈確認線上生效（輪詢新內容出現，不要用固定 sleep）
5. 報告時要講：**哪些數字你無法獨立確認**、留了哪些 `TODO（醫師補充）`、
   `sources_period` 如果留空要說明原因
6. 問他要不要送 Search Console（見 `publish-and-index` skill）
